## What was rejected, and why it is NOT agent fault (second time)
SQLi initially scored **8 of 14 UNVERIFIED**. Not fabrication: WSTG moved
`07-Input_Validation_Testing/05-Testing_for_SQL_Injection` to
`07-Injection/05-SQL_Injection`, so every cited URL was a 404, and the
published page is a JavaScript SPA whose prose never appears in a plain HTTP
fetch.

Two new modules fix this class of loss:
* `wks/resolver.py` — resolves a stale citation to its live location, but only
  accepts a candidate that **actually contains the quote**. It cannot launder a
  dead URL onto an unrelated page. 5 of 8 resolved; the other 3 correctly
  refused.
* `wks/pipeline.py` — detects an SPA shell and falls back to the upstream
  source file, recording which URL actually supplied the text.

Bug found in both while building: `--apply` computed resolutions and never
wrote them, reporting "RESOLVED" while the file kept the dead URLs. A flag
that does not write is worse than no flag.

## What changed
- `wks/methodgen.py` (new) — derives the hunting procedure from verified items
  in hunting order. This was the Methodology Agent role in the spec, and it was
  **missing entirely**: the `methodology` column was empty on all 15 classes.
  Now 15/15 have one, generated as a projection so it cannot drift from its
  evidence. An empty class renders "no verified items yet — empty rather than
  plausible" instead of inventing a procedure.
- `wks/resolver.py` (new) — stale-citation resolution, quote-gated.
- `wks/pipeline.py` — SPA-shell detection with upstream fallback; `fetch_json`.
- `wks/reconcile.py` (new) — supersedes items orphaned when an agent renames
  them mid-file.
- `wks/verify_quotes.py` — normalisation variants; the earlier matcher had a
  **19% false-positive rate** and wrongly blamed the agents for it.
- `eval/test_wks.py` — now **15 tests / 48 assertions**, including T13 (quote
  matcher in BOTH directions), T14 (SPA fallback), T15 (stale-path resolution).
