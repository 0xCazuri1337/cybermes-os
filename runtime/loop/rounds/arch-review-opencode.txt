## P2: Add evidence entailment check (quote -> claim)

**VERDICT**: **Unsound as a promotion gate; sound as a downrade signal**. Without an LLM, a purely lexical entailment check reduces to keyword overlap. A claim and a definitional quote will always share vocabulary by definition — "SQL injection via the username parameter" entails "the username parameter is used" — so the gate would either pass everything (useless) or reject legitimate findings (false authority if presented as definitive).

**Strongest failure mode**: A claim "Parameter `name` is vulnerable to XSS" paired with a quote "The `name` parameter accepts user input" passes a lexical entailment check, but the actual vulnerability is unsubstantiated. The system would promote a finding that has no evidential support beyond definitional overlap.

**Simplest design that avoids it**: Only **downrade** items that fail entailment, never promote/bar them. Use a lexical overlap score that reduces the promotion score by a weighted amount rather than binary pass/fail. Alternatively, require entailment only for specific claim types (e.g., "high_confidence" items) and for others, use it as a soft signal.

**Evidence**: The brief itself notes the gameability at line 33-36: "entailment without an LLM is keyword overlap, which is gameable — a claim and a definitional quote share vocabulary."
