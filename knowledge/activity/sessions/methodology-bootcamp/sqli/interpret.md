# interpret — result -> meaning -> next action

The rows below include the results that kill hunts. Ambiguity is the normal state
of this class, not an exception to it.

| # | Result | Meaning | Next action |
|---|---|---|---|
| 1 | Quote produces a **generic 500**, no SQL wording | Undetermined. Applications error identically for any invalid value [sqli.fp_rule.generic_500_not_sqli] | Re-send the same path with no metacharacter and with a doubled quote, and compare the **full bodies**, not the status code. If the unquoted control also 500s, the error is raised before the query is built — demote. |
| 2 | Quote produces a **database-specific error naming the construct** (syntax error near `'`, unterminated string) | Strong: the quote reached a parser and the value was inside a string literal | Move to the boolean twin pair to confirm reversibility before reporting. A parser-specific error must name the construct that failed. |
| 3 | Quote produces a **400 with fixed app validation text**, byte-identical for any invalid value | Rejected at the type/validation layer; no query was built | Stop. Not injection. Separating "rejected by input validation" from "reached the data layer" is the whole test. |
| 4 | **`OR 1=1` and `OR 1=2` both return the SAME response**, byte-identical | Either escaped/parameterized, or the endpoint's response does not depend on row count | Try a *different* oracle (ordering, error-based, time, OAST) before concluding. Identical true/false indicates the value is escaped, parameterized, or never reaches a SQL parser [sqli.technique.sql_injection_is_confirmed_by_a_boolean_differential_a_co]. |
| 5 | `OR 1=1` and `OR 1=2` return the **same non-baseline** response (both differ from the clean request, both identical to each other) | **Ambiguous — the classic trap.** A differing-but-not-reversing pair is not a boolean differential. Likely a cache entry, a rate-limit/session effect, or a parse failure common to both | Invert again (`1=3`/`1=4`) and expect a third distinct value only if the oracle is real. Then replay 3× per side; non-reproducible differences are not a validated SQLi [sqli.validation.single_variable_differential]. If they hold steady, suspect caching and vary a nonce. |
| 6 | True/false **differ, but not on the first repeat** (flips between attempts) | Cache or connection-reuse artefact, not the query | Confirm by interleaving: A,B,A,B,A,B. A signal that only appears when requests are spaced is the cache. Reject or re-baseline. |
| 7 | **Ordering changes** when a CASE is appended, and the baseline ordering is deterministic (two identical repeat requests byte-identical) | Valid injection signal — the sort fragment is grammar | Proceed to column count, then positional extraction. |
| 8 | **Ordering changes**, but two identical repeat baseline requests already order differently | Rejected. The ordering is unstable for reasons unrelated to the injected expression — the key was not reaching a query | Ordering is only a valid injection signal when a repeated identical baseline request is byte-identical. Do not use order as a signal on this endpoint. |
| 9 | **Time-based**: delay tracks the payload across ≥10 alternating samples | Valid time oracle | Cross-check with an unresolvable-host request to confirm the baseline network path, then extract with conditional delays. |
| 10 | **Time-based**: delay appears on baselines too, or an unresolvable host produces a comparable timeout | Rejected. The latency is the network path, not the database | Alternating samples must show the delay tracks the payload. Re-baseline; do not file. |
| 11 | **WAF interstitial**: plain payload 403, comment-split/encoded variant 200, but **200 contains no injected data** | Not a bypass. Filter noise, or the bypassed request never reached a query | A filter bypass requires the bypassed request to return attacker-chosen data consistently. A status code that alternates across identical requests is filter noise, not a bypass. |
| 12 | **WAF interstitial**: comment-split variant 200 *and* injected data present *and* stable across repeats | Probable bypass | Verify the data is attacker-chosen and not already in the template (row 14) before claiming it. |
| 13 | **UNION**: response differs at exactly one NULL count | Column count matched; injection demonstrated | Place a string marker per position to find a typed channel [sqli.technique.union_null_type_probe]. |
| 14 | **UNION**: response differs for *every* column count including impossible ones | Rejected. The difference is template rendering, not query execution | Grep the baseline response for the literal values you injected (e.g. `1,2,3`). A value already present in the template proves the difference came from rendering. |
| 15 | **UNION**: no NULL count alters the response at all | Ineffective method — not a refutation of injection | Fall back to boolean or error-based inference [sqli.technique.union_null_type_probe]. Do not conclude "safe". |
| 16 | **ORDER BY**: every index 1..n yields an identical response | Column counting unavailable via ORDER BY | Rely on UNION NULL probing [sqli.technique.orderby_column_count_probe]. |
| 17 | **Error-based value** (e.g. a version string) appears in the response | Ambiguous: either the injection returned it, or the server always emits it | Grep the unmodified responses of other endpoints — including pages with no injectable parameter — for the same string. If present everywhere it is information disclosure, a different finding with a different fix. |
| 18 | **Comment terminator `-- -`** changes the result set | Ambiguous: either a comment was honoured, or the app trims the value | Compare against an **empty value** and a value with a trailing space. Identical results to empty mean the result change came from the value being empty, not from a comment being honoured. |
| 19 | Comment marker only | Weak at best | A comment marker only demonstrates concatenation if its effect differs from an empty value; identical results mean the marker is ordinary input, not a comment. |
| 20 | **Error echoes your input** on a parameterised call site | Verbose-error disclosure, not injection — the value never entered the statement text | However, it becomes injection if the same request *also* produces a behaviour change with the quote removed: a boolean differential, a time delta, or an OAST callback. Parameterisation is per call site, and applications routinely have a safe read path and an unsafe report, export, or search path on the same endpoint. |
| 21 | Error echoing your input, where the framework's own **string escaping** is relied on rather than binding | **Ambiguous, and unsafe to dismiss** | Quotes in the output are not evidence of safety at the statement level: a helper that quotes and doubles the value correctly still yields a value that will break the moment a second, unescaped layer concatenates it. |
| 22 | **Dollar-quoted** PostgreSQL string: payload with `$tag$` delimiters has no effect | Probably a closed literal that ignores backslashes and dollar signs | Reclassify as injection only if the attacker can supply the tag the application's own quoting chose, or if the payload is delivered **outside** the dollar-quoted region — a second statement concatenated after the function body, or a value reaching a non-dollar-quoted parameter such as a dynamic EXECUTE string. |
| 23 | **Full-text search**: operators change match results but a quote does nothing | Not yet a finding. FTS syntax is deliberately non-SQL; a payload that only changes match results is a search-behaviour quirk | Test whether the grammar surface reaches a SQL-executing construct — e.g. an FTS expression a trigger, a view, or an auxiliary function expands into further SQL. Until that chain is demonstrated, the rich query language alone is not SQL injection. |
| 24 | **Full-text search, boolean mode**: cannot break out of the quotes and cannot change boolean-mode search | Refuted as an injection point | Reject. |
| 25 | **ORM/HQL**: quote and comment payloads produce zero rows or a type error, route confirmed bound-parameter | True negative, not a missed bug [sqli.fp_rule.orm_parameterized_quote_error] | Reject — *unless* the ORM has a known injection CVE for the deployed version, or raw concatenated queries appear in that code path. Either invalidates the negative. |
| 26 | Every in-band probe null, on an endpoint that enqueues work | **Do not close.** The query may run asynchronously | OAST callback. Absence of in-band signal does not mean absence of SQLi [sqli.signal.async_query_oast_signal]. |
| 27 | OAST payload produces **no callback** and conditional delays stay within baseline jitter | Likely not injectable | Accept as a genuine negative for this parameter. This is one of the few closes the corpus authorises outright. |
| 28 | Value observed differs but the **other parameters** were varied at the same time | Unattributable | A differential found while several parameters are varied at once is not attributable to any of them. Re-run with exactly one variable changed — or exploit the two attribution shortcuts: an OAST callback from a database-assembled payload, or an endpoint that exposes the generated SQL. |
| 29 | **Extraction on MS Access** returns nothing | Expected ordering failure, not a dead end | Extraction on MS Access is gated on naming a real column such as `username`, so the guess-and-check step comes before any value can be pulled out. Reading a value with no valid column name, or a fabricated column name returning data, refutes the ordering. |
| 30 | **MS Access** `TOP`/`LAST` rejected as syntax, or accepted with rows unchanged | Refuted as row-selection controls | Stop paging; use the boolean extraction route. |

## Meta-rules this table encodes

1. **A difference is not a signal until it is attributable.** Rows 5, 6, 14, 18
   and 28 all produce "the response changed" — and all five are traps.
2. **A null result is not a negative until the oracle is known to exist.** Row 15
   and row 26 are the two places hunts usually die early.
3. **Two out-of-band negatives together are a real negative** (row 27), and that
   is the only honest close available for an asynchronous path.
4. **Always diff against the unquoted/empty control** — rows 1, 17, 18 and 19 are
   all one extra control request away from being decided correctly.
